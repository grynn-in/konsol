# konsol-exec Orchestrator — PRD backlog (ralph loop)

Design: `open_epm/docs/developer-guide/design/konsol-exec-orchestrator.md` · Epic konsol#56 (P1 #57 / P2 #58 / P3 #59).

**Loop protocol (ralph):** pick the first unchecked PRD → write failing test (TDD) → implement → tests green → commit → check it off → repeat. Pure-python core runs on host `pytest`; frappe-bound pieces get container smoke tests.

## P1 — Step engine over the existing pipeline (#57)

- [x] **PRD-1 — DAG core.** `orchestrator/dag.py`: `Step(id,type,depends_on,params)`, build graph, `toposort()`, cycle detection, validation (unknown dep, dup id). Pure-python.
- [x] **PRD-2 — Run-plan resolution.** `orchestrator/plan.py`: `build_plan(definition, params)` → ordered steps; `skip_sync` drops `airbyte_sync`; `full_refresh` sets flag on dbt steps; `scope`→`select`; fiscal_year/period→`vars`. Pure-python.
- [x] **PRD-3 — Execution state machine.** `orchestrator/state.py`: from step statuses compute `runnable()`, `is_done()`, `failed()`; `retry(step)` resets a failed step + its descendants; `resume_from(step)`. Pure-python.
- [x] **PRD-4 — Handler registry.** `orchestrator/handlers.py`: `register(type)` decorator + `get(type)`; `Handler` protocol `run(ctx)->StepResult`; built-in types registered as stubs. Pure-python.
- [x] **PRD-5 — Executor (pure core).** `orchestrator/executor.py`: `Executor(registry, sink)` drives state machine: run next runnable, record result, stop downstream on failure, honor cancel. Injected registry+sink → fully unit-testable. Pure-python.
- [x] **PRD-6 — Run Step doctype fields.** Extend `pipeline_step`: `step_id`, `step_type`, `depends_on`, `params(JSON)`, `retry_count`, `started_at`, `ended_at`, `error`. JSON field-presence test.
- [x] **PRD-7 — Pipeline Run params.** Add to `pipeline_run`: `fiscal_year`, `fiscal_period`, `scope`, `full_refresh`, `skip_sync`, `pipeline_definition`. JSON field-presence test.
- [x] **PRD-8 — Real handlers (command building).** `airbyte_sync` (writes back `last_sync_at`), `dbt_seed/run/build/test` (select/full_refresh/vars), `close_assertions`, `signoff`. Test the pure dbt-command builder.
- [x] **PRD-9 — Frappe executor binding.** `orchestrator/run.py`: `run_pipeline(run_name)` enqueued — load run, `build_plan`, drive `Executor` with a Frappe sink (update child rows + `publish_realtime`). Container smoke test.
- [x] **PRD-10 — Whitelisted API.** `start_run(definition, params)`, `retry_step`, `resume_run`, `cancel_run`. Whitelist/signature presence test.
- [x] **PRD-11 — SPA param form + timeline.** konsol-exec: launch form (year/period/scope/flags) + step timeline w/ live logs + retry/resume/cancel. JS presence test.

## P2 — Definitions, schedules, resume (#58)

Core idea: retire the hardcoded `DEFAULT_DEFINITION` constant — let users author DAGs as doctypes, schedule them, and restart finished runs from any step. Pure cores stay host-testable; frappe parts are guarded with `importorskip`.

- [x] **PRD-12 — Pipeline Definition + Step Definition doctypes.** Create `Pipeline Definition` (module Pipeline, not istable): `definition_name` (Data, unique, autoname `field:definition_name`), `title` (Data), `description` (Small Text), `enabled` (Check, default 1), `default_params` (Code/JSON — fiscal/scope/flags), `steps` (Table → Step Definition). Create `Step Definition` (istable=1): `step_id` (Data, reqd), `step_type` (Select with options = the 9 built-in types: airbyte_sync/dbt_seed/dbt_run/dbt_build/dbt_test/close_assertions/signoff/cube_refresh/sql), `depends_on` (Small Text — comma-separated step_ids), `params` (Code/JSON). Add a fixture `pipeline_definition.json` seeding the canonical **Group Close** definition mirroring `plan.DEFAULT_DEFINITION` (extract→seed→silver→gold→assertions→signoff). Register the fixture in `hooks.py`. **Test (host, JSON-load, no frappe):** both doctype JSONs expose the field set; `step_type` options ⊇ `handlers.BUILTIN_TYPES`; the seed fixture decodes to the expected step ids + dependency edges.
- [x] **PRD-13 — Definition→plan loader.** `konsol/orchestrator/definition.py`: pure `definition_to_steps(defn: dict) -> List[Step]` — parse each step's `depends_on` (comma-split, strip) and `params` (json.loads if str) into `Step`; preserve order. Frappe-guarded `load_definition(name) -> List[Step]` (function-local `import frappe`, `frappe.get_doc(...).as_dict()` → pure converter). `build_plan` already accepts a step list, so it composes unchanged. **Test (host):** `definition_to_steps` on a dict fixture → correct Steps/deps/params; round-trips through `Dag(...).toposort()` and `build_plan(...)`; bad json/params raises a clear error. `load_definition` test guarded.
- [x] **PRD-14 — Scheduling.** `Pipeline Schedule` doctype: `schedule_name` (Data, autoname), `pipeline_definition` (Link), `cron` (Data), `params` (Code/JSON), `enabled` (Check), `last_run` (Datetime), `next_run` (Datetime, read-only). Pure `konsol/orchestrator/cron.py::is_due(expr, now, last_run=None) -> bool` — a minimal 5-field cron matcher supporting `*`, `*/n`, `a-b`, `a,b,c`, and literals on minute/hour/dom/month/dow (no need for @macros). `run_due_schedules()` (frappe-guarded) queries enabled schedules, calls `is_due`, enqueues `start_run` (PRD-10) with the schedule's definition+params, stamps `last_run`. Wire into `hooks.py` `scheduler_events.cron` under `"* * * * *"`. **Test (host):** `is_due` truth table — `*/10 * * * *` at minute 0/10 true, 7 false; specific hour/dom/dow; list/range forms; the `last_run` guard prevents double-fire within the same minute. Doctype JSON field test. Text-assert hooks.py references `run_due_schedules`.
- [x] **PRD-15 — Resume-from-step + retry API.** Pure `konsol/orchestrator/resume.py::plan_resume(steps, statuses, from_step) -> dict` — validate `from_step` exists and the run is settled (no Running/Pending-runnable), build `Dag`+`RunState(statuses)`, call `resume_from`, return the new snapshot; `plan_retry(steps, statuses, step) -> dict` likewise via `retry`. Frappe-guarded whitelisted `resume_run(run_name, from_step)` / `retry_step(run_name, step_id)`: load the Pipeline Run's child steps → snapshot, apply the pure transform, persist child statuses, re-enqueue the executor (PRD-9 `run_pipeline`). **Test (host):** `plan_resume`/`plan_retry` correctness over the Group Close plan (upstream preserved, step+descendants reset, runnable set correct); errors on unknown step / unsettled run. APIs guarded.

## P3 — Lineage, resources, FX, multi-ERP (#59)

- [x] **PRD-16 — Per-step metrics + lineage.** Pure `konsol/orchestrator/lineage.py`: static `STEP_OUTPUTS` mapping step_id/type → produced tables (silver→`silver_*`, gold→`gold_*`, assertions→close suite); `lineage_for(plan) -> list[(upstream_step, downstream_step)]` from the DAG edges plus step→model edges; `summarize(snapshot, metrics) -> {total_rows, duration_s, per_step:[...], status}` where `metrics` is `{step_id: {rows, duration_s}}` recorded by the Frappe sink (started_at/ended_at on the child rows — decoupled from the executor internals). **Test (host):** lineage edges for `DEFAULT_DEFINITION`; `summarize` totals/rollup math; empty/failed-run shaping.
- [x] **PRD-17 — Resource resolver (Airbyte / dbt / ClickHouse).** Pure `konsol/orchestrator/resources.py`: `@dataclass Resource(kind, name, config)`; `resolve(kind, params, settings: dict) -> Resource` picking the connection from run params else EPM-Settings defaults, validating required keys per kind (airbyte: workspace/connection/destination ids; dbt: project_dir; clickhouse: host/db) and raising precise errors. Frappe-guarded getters `airbyte_resource()/dbt_resource()/clickhouse_resource()` (read `connector`/`EPM Settings`) + read-only `list_resources()` API for the SPA. Builds on the existing `connector` doctype (don't duplicate it). **Test (host):** `resolve` for each kind with complete/missing settings dicts (→ Resource vs clear error); precedence params>settings.
- [x] **PRD-18 — FX surfacing (konsolidat#91 B/C).** Pure `konsol/orchestrator/fx.py`: `build_fx_query(filters) -> str` — safe SQL over `epm_silver.silver_exchange_rates` (and gold lookup), filterable by from/to currency, as-of date, rate type, source; `normalize_fx_rows(rows, cols) -> [{from,to,rate,as_of,type,source}]`. Frappe/CH-guarded `get_fx_rates(**filters)` whitelisted API using the existing `from konsol.clickhouse import execute` pattern. (Part C manual-entry doctype = sub-item; this PRD lands the read view + query builder.) **Test (host):** `build_fx_query` emits expected SQL per filter combo and is injection-safe (currency codes validated `^[A-Z]{3}$`); `normalize_fx_rows` shaping incl. empty.
- [ ] **PRD-19 — Multi-ERP extract.** Extend pure `build_plan` (plan.py) to support multiple `airbyte_sync` steps and a `sources` run-param: keep only extract steps whose `params.source` ∈ `sources` (drop+rewire the rest, like `skip_sync`); all retained extracts fan into `seed`. Add `merge_sources(definition, sources)` helper. **Test (host):** a 2-extract definition (`d365`, `erpnext`); `sources=['d365']` keeps one extract + valid DAG; no `sources` keeps both; `skip_sync` still drops all extracts.
